# План продакшна и A/B-запуска

Сценарий готов (`script.md`), все 8 шагов алгоритма закрыты. Ниже — конкретные шаги
от съёмки до выбора победившей версии.

## 1. Съёмка и сбор медиа

Медиа-микс по бит-каркасу (см. `script.md`, биты 2–4 — общие для всех версий):

| Материал | Где используется |
| --- | --- |
| Архивные фото заводов конца XIX века (Paper-Cut стиль) | Бит 2, 0:03–0:16 |
| Крупные цифры-стопкадры: «~100 Ч/НЕД», «$1.5/ДЕНЬ» | Бит 2, отдельный кадр-стоп на каждую цифру |
| Спикер в профиль 45°, сверхкрупный план (для всех 3 хуков) | Хук 0:00–0:03, живой план |
| Нарезка: синхронная толпа / марш, календарь с датой, газетные заголовки 1886 г. | Бит 3, 0:16–0:30 |
| Motion-графика глобуса с подсветкой 160+ стран, затем карта США с датой | Бит 4, 0:30–0:44 |
| Чистый кадр для hard cut в конце | Петля/панч, 0:44–0:52 |

Если архивных материалов нет в библиотеках стока — использовать общественное достояние
(Library of Congress, Wikimedia Commons) с указанием источника, не чужие вотермарки.

## 2. Монтаж

- Темп: смена плана/цифры/стикера каждые ~1.5–2.5 сек.
- Бит 2: склейка каждые ~1.5 сек, SFX-затвор на каждой всплывающей цифре.
- Бит 3: глитч + whoosh-переход, нарастающий riser под монтаж.
- Бит 4: плавный пролёт по карте, дроп бита на финальной цифре «160+».
- Петля: hard cut на чистый кадр + резкий обрыв трека — это должно грамматически
  стыковаться с началом хука следующего просмотра.
- Хук: без раскачки, sub-bass boom сразу на первом кадре.

## 3. Титры и субтитры

- Хук-титр: 3–4 слова, выше линии глаз, safe-zone 25–32% экрана.
- Караоке-субтитры на всю дорожку: активное слово #FFE600, зона 48–55% высоты экрана.
- Крупные цифры: по центру, до 30% высоты; #00FF66 (лайм) — положительный итог,
  #FF2A2A (красный) — острые/шоковые моменты.
- Титр петли — вопрос со стрелкой (↓ что передоговоришь? / ↓ твоя сделка? / ↓ где применишь?).

## 4. Факт-корректировка (внесена)

В блоке «Завязка» закадровый текст скорректирован: «$1.5/день» подаётся как «ставка от
полутора долларов в день», а не как заданная средняя зарплата. По первоисточникам это
лозунг-требование из забастовочной листовки железнодорожников, а не задокументированная
средняя зарплата (в отличие от «~100 ч/нед» — это гособмер условий труда 1890 г.). Титр
«$1.5» в кадре можно оставить как есть — краткая форма читается как порядок цифры, детальную
оговорку несёт закадровый текст. См. `factcheck.md`.

## 5. Публикация и A/B-тест через Trial Reels

Порядок именно последовательный, не параллельный — иначе три ролика с идентичной серединой
рискуют быть распознаны как малооригинальный дублирующийся контент (Originality Score) и
получить заниженный охват у всех трёх сразу.

1. Собрать 3 полных монтажа (A/B/C) — отличаются только хук + петля.
2. Загрузить **версию A** через Trial Reels (тест на пуле не-подписчиков, не попадает в ленту
   подписчиков и не публикуется как отдельный публичный пост).
3. Дождаться статистики теста, зафиксировать метрики (см. ниже).
4. Повторить для версии B, затем версии C.
5. Сравнить все три по единым метрикам и выбрать победителя.
6. Опубликовать победившую версию как обычный Reels-пост с соответствующим закреплённым
   комментарием из `script.md`.
7. Разнести хэштеги 3–5 шт: #бизнес #переговоры #история #стратегия #предприниматель.

### Метрики сравнения (в порядке значимости)

1. Удержание на 3-й секунде (выживаемость после хука) — главный показатель силы крючка.
2. Completion rate (% досмотревших до конца) и replay rate (мгновенный пересмотр).
3. Sends — репосты в личку/сторис (по значимости для охвата примерно в 3–5 раз выше лайка).
4. Соотношение лайков к охвату (не абсолютное число).

### Критерий выбора победителя

Версия-победитель — та, что лидирует по удержанию на 3-й секунде **и** по completion rate;
при расхождении (одна выигрывает по хуку, другая — по досмотру) приоритет отдаётся
удержанию на 3-й секунде, поскольку без него остальные метрики не набираются вообще.

## 6. После публикации

- Первые ~90 минут — решающее окно: не редактировать пост, не удалять и не перезаливать.
- Сразу оставить закреплённый комментарий-вопрос из `script.md` (версия победителя).
- Мониторить удержание и sends в первые часы; данные использовать для следующего сценария.
